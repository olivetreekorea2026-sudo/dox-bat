DOX KOREA — ЗАПУСК ВМЕСТЕ С DOX GLOBAL НА ОДНОМ БЕСПЛАТНОМ СЕРВЕРЕ
===================================================================

Эта версия НЕ заменяет app.py и bot.py международного DOX Global.
Не удаляйте и не переименовывайте файлы DOX Global.

В архиве:
  korea_bot.py       — отдельная программа DOX Korea
  korea_catalog.py   — названия/диоптрии по 7 каталогам
  korea_images/      — ваше изображение PREMIUM SET 1 и 7 новых каталогов
  run_both.py        — одновременный запуск двух ботов

ПЕРВЫЙ ШАГ — СОЗДАТЬ БОТА
1. Откройте @BotFather в Telegram: https://t.me/BotFather
2. Отправьте /newbot, задайте имя «DOX Korea».
3. Задайте УНИКАЛЬНЫЙ username с окончанием «bot», например dox_korea_orders_bot,
   если он свободен. Не используйте токен международного DOX Global!
4. Скопируйте токен от BotFather. НИКОМУ не отправляйте его,
   не публикуйте токен в GitHub, скриншотах и переписке.

ВТОРОЙ ШАГ — ДОБАВИТЬ В СУЩЕСТВУЮЩИЙ GITHUB
1. Откройте существующий репозиторий DOX Global (dox-bat).
2. Добавьте в корень (на одном уровне с существующими app.py и bot.py)
   три файла run_both.py, korea_bot.py, korea_catalog.py.
3. Добавьте папку korea_images со всеми восьмью JPG-фотографиями.
   Важно: файлы должны лежать по пути korea_images/premium_set.jpg и др.
4. Нажмите Commit changes.
5. НЕ заменяйте уже работающие app.py, bot.py, каталоги DOX Global.
6. requirements.txt международного бота должен содержать:
     aiogram>=3.13,<4
     python-dotenv>=1,<2
   Если уже содержит обе строки — не меняйте.

ТРЕТИЙ ШАГ — ПРИВАТНЫЕ ПЕРЕМЕННЫЕ СЕРВЕРА SILLY DEVELOPMENT
В .env на существующем сервере (или Variables) оставьте старый BOT_TOKEN
без изменений, а НОВЫМИ строками добавьте:

   KOREA_BOT_TOKEN=ВСТАВЬТЕ_НОВЫЙ_ТОКЕН_ОТ_BOTFATHER
   KOREA_BANK_ACCOUNT=ВСТАВЬТЕ_НОМЕР_СЧЕТА_KAKAO_BANK
   KOREA_BANK_HOLDER=ВСТАВЬТЕ_ИМЯ_ПОЛУЧАТЕЛЯ_НА_КОРЕЙСКОМ
   KOREA_OWNER_ID=ВАШ_ЧИСЛОВОЙ_TELEGRAM_ID

Чтобы узнать Telegram ID владельца: откройте нового бота, напишите /myid,
скопируйте числовой ID и добавьте его в .env под KOREA_OWNER_ID.
После этого перезапустите бота. Без KOREA_OWNER_ID команда /bind заблокирована,
чтобы посторонние не смогли привязать свои группы и получать данные клиентов.

Вам уже известны номер счёта Kakao Bank и получатель 구자효 —
впишите их в приватный .env на сервере, НЕ в публичный GitHub.
Не размещайте настоящий .env в репозитории.

ЧЕТВЁРТЫЙ ШАГ — ЗАПУСК
1. Silly Development → Console → Stop.
2. Silly Development → GitHub → Deploy now.
3. Silly Development → Startup → APP PY FILE = run_both.py
4. REQUIREMENTS FILE = requirements.txt.
5. Console → Start. В консоли должны быть успешные запуски ОБОИХ ботов.
6. Если сообщения о недостатке памяти, старые боты остановлены не полностью,
   либо другие ошибки — пришлите безопасный скриншот логов без токена.

ПЯТЫЙ ШАГ — ПРИВЯЗАТЬ КАЖДОГО КРЕАТОРА К СВОЕЙ ГРУППЕ
По умолчанию работают коды CREATOR01 и CREATOR02.
1. Создайте закрытую группу «DOX Korea — CREATOR01».
2. Добавьте НОВОГО бота DOX Korea и назначьте его администратором группы.
3. Администратор группы отправляет /bind CREATOR01
4. Бот отвечает персональной ссылкой: https://t.me/USERNAME_BOT?start=CREATOR01
5. Аналогично создайте отдельную группу «DOX Korea — CREATOR02».
6. Добавьте бота и отправьте /bind CREATOR02
7. Бот отвечает ссылкой: https://t.me/USERNAME_BOT?start=CREATOR02

ВАЖНО: username нового DOX Korea назначается через BotFather, а не DOX Global.
Простой /start без ссылки не позволяет новому покупателю оформить заказ.
Перейдя по персональной ссылке, клиент привязывается к коду продавца.
При новом переходе по ДРУГОЙ ссылке код для будущих заказов меняется;
для уже оформленных заказов продавец не меняется.
Каждый заказ и фото оплаты автоматически отправляются в группу нужного креатора.
После подтверждения оплаты клиент получает уведомление; после отправки —
трек-номер. Менеджер может ответить клиенту через Reply.

Чтобы добавить креаторов позже, в секретном .env на Silly Development укажите:
KOREA_CREATOR_CODES=CREATOR01,CREATOR02,CREATOR03
Перезапустите оба бота, создайте новую группу, отправьте /bind CREATOR03.
Смена кодов в .env не удаляет данные уже оформленных заказов.
Если код уже привязан к другой группе, бот НЕ разрешит повторную привязку.
Никогда не показывайте покупателям ссылку-приглашение в закрытую группу.

ПРОВЕРКА
1. Откройте нового DOX Korea ПО ССЫЛКЕ CREATOR01 и отправьте /start CREATOR01.
2. Вы увидите ваше фото PREMIUM SET 1, стоимость 100 000 ₩.
3. Нажмите «Заказать» → 3 пары → имя/фамилия латиницей → телефон,
   индекс, адрес корейскими буквами → проверка заказа.
4. ПОКА НЕ ПЕРЕВОДИТЕ РЕАЛЬНЫЕ ДЕНЬГИ. Выполните тестовое оформление.
5. После подтверждения проверяйте реквизиты на экране, а затем
   прикрепите тестовое фото вместо настоящего платёжного чека.
6. У менеджера чек появится в группе CREATOR01. Нажмите «Оплачен».
7. Бот уведомит клиента. «Отправлен» попросит трек-номер в ответном сообщении.
8. Повторите тест со ссылкой CREATOR02 и убедитесь, что заказы не попадают в группу CREATOR01.

ОГРАНИЧЕНИЯ И БЕЗОПАСНОСТЬ
- На одном бесплатном аккаунте Silly Development обычно доступен ОДИН
  бесплатный сервер, поэтому два бота могут жить в одном процессе
  (при достаточном объёме оперативной памяти).
- DOX Global и DOX Korea используют РАЗНЫЕ токены, базы и группы.
- Для Korea в таблице заказов хранится creator_code, а у каждого креатора своя группа.
- DB Korea: data/dox_korea.db — хранится отдельно от DOX Global.
- Регулярно делайте резервную копию БД с личными данными клиентов.
- В бот не встроена автоматическая банковская проверка. Менеджер
  подтвердит деньги только после фактического поступления на счёт.
- Проверка диоптрий в боте основана на каталогах; точное наличие товара
  менеджер должен подтверждать перед сборкой/отправкой заказа.
